# AGENTS.md

Guidance for AI coding agents working in `settingsync.koplugin`. Read this before touching any file.

## Global rule: search KOReader core first

Before writing ANY code — a new Lua utility, UI pattern, or API call — **always search
the sibling `koreader/` folder** for existing implementations.
KOReader ships a large frontend library (`frontend/`, `plugins/`) — reuse its helpers,
widgets, and conventions rather than reinventing them.

## What this plugin is

A KOReader plugin that **synchronizes KOReader settings across devices via WebDAV** with
per-key diffing and selective sync. It reads and writes `.lua` settings files (LuaSettings
format), downloads the remote copies into a temp dir for comparison, then lets the user
choose which individual keys to push or pull before applying changes.

## File map

- `main.lua` — plugin entry point: menu registration (`buildMainMenu`), WebDAV upload /
  download orchestration, quick push/pull, settings-file I/O, scope settings,
  per-key excluded-key filtering,
  device profile management, and category sync workflow.
- `settingsync_diff.lua` — **pure, stateless** diff engine. `Diff.compare(local, remote)`
  returns an array of `{key, status, local_val, remote_val}` entries sorted by key name.
  Status values: `ADDED`, `REMOVED`, `MODIFIED`, `UNCHANGED`.
- `settingsync_ui.lua` — `DiffViewer` widget: scrollable per-key diff table, tap to cycle
  push/pull per row, **Push all** / **Pull all** bulk actions, and **Apply** callback.
  Accepts an optional `category` field; when set, key names and values are rendered using
  the category's human-readable labels and value formatters instead of raw Lua dumps.
  Stores a `scrollable` reference so `refreshUI()` can preserve the scroll offset across
  row-tap redraws.
- `settingsync_categories.lua` — category definitions. Each category describes a logical
  group of settings keys that can be synced independently (e.g., `Categories.GESTURES`
  covers gesture keys from `settings/gestures.lua`). Provides `Categories.extract()`,
  `Categories.keyLabel()`, `Categories.formatValue()` helpers used by `DiffViewer`, and
  the dynamic discovery function `Categories.discoverPluginSettings()` (per-plugin
  `settings/*.lua`), see below.
- `settingsync_devices.lua` — device profile utilities. `Devices.currentName()` reads the
  user-assigned device name from plugin settings. `Devices.remotePath()` builds cloud
  paths like `devices/{device_name}/{remote_name}`. `Devices.listFromCloud()` discovers
  device names by listing the `devices/` folder on the WebDAV server, and
  `Devices.listUploads()` lists one device's uploaded files.
- `insert_menu.lua` — injects the `"settingsync"` entry into both the File Manager and
  Reader tool menus, after the `"statistics"` item.
- `settingsync_gettext.lua` — pure-Lua gettext subset (adapted from `assistant.koplugin`).
  Loads `.po` files from `l10n/` at runtime.
- `l10n/zh_CN/koreader.po`, `l10n/zh_TW/koreader.po` — Simplified and Traditional Chinese
  translation catalogs.
- `_meta.lua` — plugin metadata (name / version / description).
- `.luacheckrc` — Luacheck config: `std = "luajit"`, `globals = {"G_reader_settings"}`,
  line-length warning 631 suppressed.

## Menu structure

The menu is modelled on a typical consumer sync screen: one primary action, a
status line, account/device setup, a "what to sync" chooser, and a drawer for
power features. `buildMainMenu()` returns the top-level `sub_item_table`:

```
SettingSync
├── Sync now                    (primary; smart two-way merge — see below)
├── {status line}               (enabled=false info: "Not set up yet" /
│                                "Not synced yet" / "Last synced: …")   [separator]
├── Cloud account: {name}       (tap → configure; text_func)
├── This device: {name}         (tap → rename; text_func)
├── Devices in cloud…           (showCloudDevices — every profile in devices/) [separator]
├── What to sync ▸              (buildWhatToSyncMenu — group toggles)    [separator]
└── Advanced ▸                  (buildAdvancedMenu)
    ├── Review and choose each change…   (diffAndSync)                   [separator]
    ├── Restore from another device ▸    (buildRestoreMenu — categories) [separator]
    ├── Force upload — overwrite cloud   (quickSync "push")
    └── Force download — overwrite this device  (quickSync "pull")
```

Design rules:
- **`Sync now` is the only action a normal user needs.** It never shows raw keys unless
  there is a genuine conflict. Keep it first and keep it dumb-simple.
- Per-key review, force push/pull, and category restore are **power features** and must
  stay under `Advanced ▸`. Do not promote them back to the top level.
- Category entries (device-specific groups like Gestures) live under
  **Advanced ▸ Restore from another device**, generated by iterating
  `self:getAllCategories()` in `buildRestoreMenu()`. Adding a category to `Categories.ALL`
  (or shipping a plugin `settings/*.lua`, auto-discovered —
  see below) makes it appear there automatically — do not add a top-level "Sync: X" item.
- The status line uses `enabled_func = function() return false end` so it renders as a
  non-tappable caption. Its text comes from `SettingSync:statusText()`.

## Smart sync ("Sync now")

`syncNow()` → `_doSyncNow()` implements a two-way merge that is safe for non-technical
users:

1. For each scope source, download the cloud copy and `Diff.compare` against local
   (after stripping `exclude_keys`).
2. Classify each changed key:
   - `ADDED` (local only) → auto **push**.
   - `REMOVED` (cloud only) → auto **pull**.
   - `MODIFIED` (both changed) → **conflict**, collected for user resolution.
3. If there are no conflicts, `_finishSyncNow()` applies all auto selections via
   `applyDiffSelections`, stamps `last_sync = os.time()`, and shows a
   "%d uploaded, %d downloaded" summary.
4. If there are conflicts, `_resolveConflicts()` shows a `ButtonDialog` offering
   **Keep this device** (push all), **Keep cloud** (pull all), **Choose for each…**
   (`_reviewConflicts` applies the auto changes then opens the diff viewer limited to the
   conflicting keys via `showDiffChain`), or **Skip them** (conflicts stay as they are on
   both sides, one-sided changes still sync).

Invariants for agents:
- `_doSyncNow` reuses `applyDiffSelections` for the actual writes/uploads — do **not**
  duplicate merge logic. `exclude_keys` stripping happens once, before classification.
- Auto-classification is intentionally two-way with no baseline: local-only ⇒ push,
  cloud-only ⇒ pull. There is no three-way merge; do not add "deletion" detection without
  a stored baseline.
- `last_sync` is a Unix timestamp in `settingsync.lua`; `statusText()` formats it.

## Category-agnostic notes

There is no separate "sync source" model beyond categories — `Categories.ALL` (static)
plus `Categories.discoverPluginSettings()` (dynamic) together are the single list every
menu and sync path iterates via `SettingSync:getAllCategories()`. Do not reintroduce a
parallel `SOURCES` table or `sync_scope.*` settings; extend the category model instead
(add a static category, or extend a `discover*` function / add a new one for another
dynamic source).

**No key should ever need to be added by hand.** Four mechanisms guarantee this, and any
change must preserve all four:

1. `Categories.READER_OTHER` is a **catch-all** (`residual_of = READER_SETTINGS`). It owns
   every key in `settings.reader.lua` that no other category claims, so a setting added
   upstream syncs the day it appears. Narrowing a category's `keys` list is therefore
   safe; a new key is never lost, it just lands in "Other reader settings".
2. `Categories.READER_SECRETS` claims every credential-shaped key in the same file
   (`key_patterns = CREDENTIAL_KEY_PATTERNS`). Usernames, passwords, logins and API keys
   are settings users want carried to a new device, so they sync like anything else — the
   category exists to *group* them under one switch, not to hold them back. A password
   upstream adds tomorrow is matched by shape and covered the day it appears. It is itself
   `residual_of = READER_SETTINGS`, so a credential-shaped key a feature category already
   owns (`xray_sync_server` matches `_servers?$`) stays with that category rather than
   being claimed twice.
3. `Categories.discoverPluginSettings()` covers every `settings/*.lua` file not claimed by
   a static category, recursing into sub-folders, so a newly installed plugin needs no code
   change here. Two filters apply. Names that look like volatile state are skipped, matched
   on the **trailing** name part only (`VOLATILE_FILE_PATTERNS` — `history`, `queue`,
   `cache`, `stats`), so `bookinfo_cache.lua` and `battery_stats.lua` are dropped but
   `cache_policy.lua` is not. And
   `isSettingsDump()` reads the header line-wise, skipping blank and `--` lines until it
   finds `return {`; a `--[[` block comment means hand-written source and disqualifies the
   file. Re-serializing hand-edited source via `dump()` would destroy it on the first pull,
   so when in doubt the file is skipped.
4. `Categories.DEFAULTS_CUSTOM` covers `defaults.custom.lua` with `all_keys`, so
   overrides of KOReader's built-in defaults port too, one key at a time.
Prefer `key_prefix` over an explicit `keys` list whenever a feature owns a namespace, so
new sub-settings are picked up by their own category rather than falling to the catch-all.
A key must be claimed by at most **one** category per source file; two owners means the
user is asked about the same setting twice.

Never add device-specific keys to the sync path. `Categories.owns()` enforces exclusion
before ownership, and `UNSYNCABLE_KEY_PATTERNS` (`_dirs?$`, `_paths?$`, `_folders?$`,
`^last`, `^dev_`, `^device_id$`, plus `^/` and `^%a:[/\\]` for keys that *are* absolute
paths, as in `settings/directory_defaults.lua`) is applied to **every** category
automatically — it is not named in any category definition. That way a path-shaped key
upstream adds tomorrow is dropped by shape wherever it lands, including inside `all_keys`
categories such as `CLOUD_STORAGE` (whose `download_dir`/`upload_dir` stay per-device).
Two escape hatches remain, for keys the shape filter cannot judge:

- `exclude_keys = {…}` — exact key names. Only needed for keys that are unsyncable but
  *not* path-shaped (`screensaver_image`, `screensaver_cycle_index`, `ko_version`).
- `exclude_patterns = {…}` — extra per-category Lua patterns. Prefer widening
  `UNSYNCABLE_KEY_PATTERNS` instead, so every category benefits.

`opaque_keys = true` opts a category *out* of the shape filter (used for `WIFI_NETWORKS`,
whose keys are SSIDs like `"Home_paths"`, not KOReader setting names).

Credentials are **not** on that list. Accounts, passwords and API keys are part of the
setup a user expects to arrive on a new device, so they are claimed by `READER_SECRETS`
(or by the plugin category that owns their file) and sync like any other setting. Do not
"harden" this by excluding them — it silently strands the user's logins on one device.
The cloud folder therefore holds secrets in plain text; that is the accepted trade-off,
and the WebDAV credentials protecting it are the security boundary.

Exclusion and inclusion are separate predicates (`isExcluded` / `claims`) precisely so the
catch-all can distinguish them: `residual_of` skips a key that another category *claims*
**or** *deliberately excludes*. Without that, excluding e.g. `screensaver_image` from
`SCREEN` would silently hand it to "Other reader settings" and sync it anyway.

Because exclusion lives in `owns()`, an excluded key is invisible to *every* code path —
extraction, diffing, and the write-back in `mergeCategoryIntoFile()`. Downloaded data is
passed through `Categories.extract()` too, so a remote dump written by an older or newer
category layout can never reintroduce a key this device must not sync.

`readSettingsData()` returns `data, ok`. A missing file is `{}, true`; a file that exists
but cannot be read or parsed is `{}, false`. Never ignore the flag: an unreadable file is
indistinguishable from an empty one, so writing it back would truncate the user's settings
and a diff against it would show every remote key as new. Every sync path skips the
category instead, and `mergeCategoryIntoFile()` returns false without writing.

## Downloaded dumps are data, never code

`loadDump()` parses settings dumps with `loadstring` + `setfenv(chunk, {})` (falling back
to `load(…, "t", {})`), and rejects any file starting with the `\27` bytecode marker.
**Do not replace it with `dofile()`.** The same function parses the copy just downloaded
from the cloud, and it runs during *diffing* — before the user has approved anything, so
"Review and choose each change…" offers no protection. A dump is nothing but literals, so
an empty environment costs a legitimate file nothing while `os`, `io` and `require` come
back nil for anything else; the bytecode check matters because LuaJIT would otherwise map
a precompiled chunk in unchecked. A file that fails returns `{}, false`, so the category
is skipped rather than truncated.

`readSettingsData()`/`writeSettingsData()` keep a `source_cache` of the **on-device** files
(never downloaded copies), cleared by `resetSourceCache()` at the start of each
user-initiated run. It is not only a speed-up: a dozen categories share
`settings.reader.lua`, and re-reading it per category calls `G_reader_settings:flush()`,
which would write the in-memory copy back over a merge that had just been written to disk.
Any new sync entry point must call `resetSourceCache()` before its first read.

## Pulls are additive

`mergeCategoryIntoFile()` adds and overwrites the pulled keys and touches nothing else. It
must **not** clear a category's existing keys first: with `READER_OTHER` owning most of
`settings.reader.lua`, deleting by absence would let one force pull against a partial or
stale backup reset the whole device to KOReader's defaults. The cloud copy is a backup of
some device's setup, not an inventory of what this device may keep, and "Force download"
promises to overwrite settings, not to delete ones the backup never had. **A pull adds and
updates; it never deletes.** `syncToGlobalSettings()` mirrors the same keys into the live
`G_reader_settings` for the same reason.

## Pulls into files other code holds open

Only `settings.reader.lua` is mirrored back into memory, by `syncToGlobalSettings()` —
without it `G_reader_settings:flush()` at exit would overwrite the file we just wrote.
Every other target (`settings/*.lua`, `defaults.custom.lua`) is
owned by some other plugin's live `LuaSettings`/`LuaDefaults` object that this plugin
cannot reach, so a pull there is invisible until restart and may be flushed over on exit.
`mergeCategoryIntoFile()` therefore sets the module-level `restart_needed` flag whenever it
writes a path other than `READER_SETTINGS`, and each terminal sync path
(`showDiffChain` at the end of the chain, `_finishSyncNow`, `_doQuickSync`,
`_applyCategorySelections`) calls `showRestartNoticeIfNeeded()`, which fires
`UIManager:askForRestart()` once and clears the flag. Any new pull path must call it too.

## Category defaults

`categoryEnabled(scope, category, default_all)` in `main.lua` is the single source of truth
for whether a category syncs. `sync_categories[id]` is tri-state: `nil` means "use the
default", `true`/`false` are explicit user choices. `sync_categories_default` records the
last **Select all** / **Deselect all** press, so a category discovered *after* that press
inherits the user's intent instead of silently switching itself on.

## Category-based sync model

Categories are defined in `settingsync_categories.lua`. Each category:

```lua
{
    id               = string,   -- e.g. "gestures"
    label            = string,   -- translated display name, e.g. _("Gestures")
    description      = string,   -- translated description
    local_path       = string,   -- absolute path to the source file on device
    remote_name      = string,   -- filename in cloud, e.g. "gestures.lua"
    opaque_keys      = bool,     -- keys are user strings (SSIDs), not setting names
    -- Exactly one extraction mode:
    keys             = {string}, -- only these top-level keys
    key_prefix       = string|{string},  -- every key starting with this prefix / any of them
    key_patterns     = {string}, -- every key matching any of these Lua patterns
    all_keys         = true,     -- the entire settings file
    residual_of      = string,   -- catch-all: every key in this file no other category owns
    -- Applied before any mode, so an excluded key is owned by nobody:
    exclude_keys     = {string}, -- exact key names never synced
    exclude_patterns = {string}, -- extra Lua patterns on top of UNSYNCABLE_KEY_PATTERNS
    key_labels       = {[key]=string},  -- translated human-readable names per key
    value_formatters = {[key]=fn},      -- optional per-key value display functions
    value_formatter  = fn,              -- fallback formatter when keys are not fixed
}
```

Category-based sync workflow in `main.lua`:
1. User selects a category (e.g., **Gestures**) from **Advanced ▸ Restore from another
   device**.
2. If multiple device profiles exist in cloud, a device picker appears.
3. `_doCategorySync(category, target_device_name)` downloads
   `devices/{target_device}/{category.remote_name}` and diffs it against the locally
   extracted category keys from the category's `local_path`.
4. `DiffViewer` shows the diff with human-readable key labels and formatted values.
5. On Apply: pulls replace the category's portion of the local source file (all owned keys
   are cleared, then the merged set is written back); pushes upload to
   `devices/{my_device_name}/{category.remote_name}`.

### Extraction modes and `Categories.owns`

`Categories.owns(category, key)` is the single source of truth for which keys a category
covers. It is built from two helpers: `isExcluded()` (`exclude_keys` / `exclude_patterns`,
checked first) and `claims()` (`all_keys` / `key_prefix` / `key_patterns` / `keys`,
inclusion only). `residual_of` is evaluated between them. Both `Categories.extract()`
(read side) and `_applyCategorySelections()` pull path (write-back side) use it, so a
category always round-trips exactly the keys it owns. When adding a mode, update `claims`
only — the rest follows.

`residual_of` is resolved by asking every non-residual category with the same source file
whether it `claims` **or** `isExcluded`s the key. A residual category that *also* has claim
rules (`READER_SECRETS`) then narrows what is left; a residual category with **no** claim
rules (`READER_OTHER`) is the last resort and yields to those. Keep one last-resort
catch-all per file.

## DiffViewer status icons

| Icon | Meaning | Natural default action |
|------|---------|----------------------|
| `≠`  | Key exists on both sides with different values | Either direction |
| `↑`  | Key exists **locally only** (not in cloud) | Push to cloud |
| `↓`  | Key exists **in cloud only** (not local) | Pull from cloud |

These icons appear in the row header (before the key name) and in the summary line at the
top of the diff viewer. The cycling order on tap: nil → direction-default → other → nil.

## Device profile model

Device profiles are managed by `settingsync_devices.lua`:
- The current device name is stored in `settingsync.lua` as `device_name`.
  Default: `"default"`.
- Device-specific category files live at `devices/{device_name}/{remote_name}` in the
  cloud folder. `Devices.remotePath(name, remote_name)` builds this path.
- `Devices.listFromCloud(server)` lists the `devices/` folder to discover known devices.
- `Devices.listUploads(server, name)` lists what one device has uploaded, as remote names
  relative to its folder. It issues its own Depth-1 `PROPFIND` rather than calling
  `WebDavApi:listFolder()`, which hides every file KOReader has no reader for — and every
  file this plugin uploads is a `.lua`. The `plugin_settings/` sub-folder is walked
  within a fixed request budget.
- **Devices in cloud…** (`SettingSync:showCloudDevices()`) shows the result as a
  `KeyValuePage`: one row per profile, the current one marked, the value being how many
  groups it has backed up; tapping a row lists them by category label
  (`SettingSync:remoteLabel()` maps `remote_name` → label, falling back to the file name
  for plugins this device does not have).
- Users set their device name via **Device: {name}** in the SettingSync menu.

## Diff / apply contract

`settingsync_diff.lua` is a **pure function module** — it must never require UI or
side-effectful modules.

- `Diff.compare(local_data, remote_data)` — returns sorted array of diff entries.
- `Diff.changesOnly(entries)` — filters to `ADDED | REMOVED | MODIFIED` only.
- `Diff.deepEqual(a, b)` — recursive value equality (used to classify `UNCHANGED`).
- `Diff.prettyValue(val)` — single-line human-readable preview for display.
`DiffViewer` calls `Diff.compare` then drives `on_apply(selections)` back into `main.lua`.
`selections` is an array of `{entry = diff_entry, direction = "pull"|"push"}`.
The viewer is also a chain step, so it reports the two ways out that change nothing:
`on_skip()` (leave this group alone, caller moves to the next) and `on_cancel()` (stop the
run here; also fired by the Cancel button and the close swipe). The **Skip** button only
appears when the caller supplied `on_skip` — for a one-off viewer Cancel already means the
same thing.

## i18n rule

All user-visible strings **must** go through `settingsync_gettext.lua` (aliased as `_`).

- Load at the top of each Lua file that shows UI: `local _ = require("settingsync_gettext")`.
- Wrap every user-visible string: `_("Your string here")`.
- When you add a new string, add it to **both** `l10n/zh_CN/koreader.po` and
  `l10n/zh_TW/koreader.po`.
- Never hardcode a translated string directly in Lua files.
- **Never bind `_` as a loop variable in a file that aliases `_` to gettext.**
  `for _, v in ipairs(t)` shadows the alias for the whole loop body, so any `_("…")`
  inside it crashes at runtime with *attempt to call local '_' (a number value)* — and
  neither Luacheck nor `check_i18n.py` catches it. Use `_i` / `_j` instead.
- **Never concatenate a non-ASCII string literal with `_()`.**  Patterns like
  `"\u2713 " .. _("key")` produce partially-translated strings that `check_i18n.py` will flag.
  Put the whole visible string into a dedicated translation key instead.

## Build / test / lint

- **No build step** — Lua files run directly in KOReader.
- **Lint**: `luacheck -q .` from inside `settingsync.koplugin/` (the `.luacheckrc` is
  already configured).
- **i18n check**: `python check_i18n.py` from inside `settingsync.koplugin/`.
  Scans every `_()` call in all `.lua` files and verifies each string has a `msgid` entry in
  **both** `l10n/zh_CN/koreader.po` and `l10n/zh_TW/koreader.po`. Exit 0 = clean.
  **Run this after every change that touches a `.lua` file or a `.po` file.**
- **Manual test**: configure WebDAV on two KOReader instances, change a setting on one,
  use Compare & Sync on the other, and confirm the diff view correctly shows the changed
  key and that applying push/pull updates the right file.

## Change checklist for agents

When editing diff logic in `settingsync_diff.lua`:

1. `Diff.compare` must remain a pure function — no I/O, no global state.
2. The status constants (`ADDED`, `REMOVED`, `MODIFIED`, `UNCHANGED`) must not be renamed
   without updating all consumers (`settingsync_ui.lua`, `main.lua`).
3. `changesOnly` must filter to non-`UNCHANGED` entries only — `DiffViewer` relies on this
   to detect the "no differences" early-exit case.

When editing sync orchestration in `main.lua`:

4. `exclude_keys` filtering must be applied **before** upload and **after** download — keys
   on the exclusion list must never travel in either direction.
5. Scope gates (`sync_scope`) must be checked in `getSources()`, not scattered in callers.
6. Cloud files must be downloaded to `TEMP_DIR` and cleaned up after the operation — never
   write directly to `SETTINGS_DIR` without going through the merge/apply path.
7. Directory creation uses `lfs.mkdir(dir)` — **never** `os.execute('mkdir -p ...')`.

When editing the menu in `main.lua`:

8. `buildMainMenu()` holds only the primary flow (Sync now / status / account / device /
   What to sync / Advanced). Category items belong in `buildRestoreMenu()` under
   **Advanced ▸ Restore from another device** — do **not** move them to the top level.
9. The `server_ok` closure gates `enabled_func` for all cloud operations; do not duplicate
   the `readSetting("sync_server")` check elsewhere.
10. **Always use `sub_item_table_func`, never `sub_item_table = self:buildFoo()`.**
    KOReader's `filemanagermenu.lua` calls `addToMainMenu` inside a `pcall`. Any runtime
    error — including one thrown by an eagerly-called `buildFoo()` — is silently swallowed
    and the plugin's entire menu entry disappears without any log message. The lazy form:
    ```lua
    sub_item_table_func = function() return self:buildMainMenu() end
    ```
    defers execution to tap-time, so a bug in `buildMainMenu` shows an error dialog instead
    of silently erasing the menu. This applies to the root plugin entry **and** any nested
    submenu item whose table is built by a method call.

When adding a new category to `settingsync_categories.lua`:

11. Add the category table to `Categories.ALL`. It appears automatically under
    **Advanced ▸ Restore from another device** via `buildRestoreMenu()`.
12. Use `_("English string")` for all `key_labels` values so `check_i18n.py` finds them.
13. All keys for one category should live in a single source file; set `local_path`
    explicitly (see `Categories.GESTURES` which points to `settings/gestures.lua`).

When editing `DiffViewer` in `settingsync_ui.lua`:

14. `buildUI()` must assign `self.scrollable` and `self.cropping_widget` to the
    `ScrollableContainer` it creates, so `refreshUI()` can read `_scroll_offset_y` to
    preserve the user's scroll position across row-tap redraws.
15. `refreshUI()` saves `_scroll_offset_y` before closing and restores it after rebuilding —
